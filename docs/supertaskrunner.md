# 任务系统架构约束

此文档描述当前 `app/network/` 的任务编排与 `app/tui/` 的进度展示。旧 SuperTaskRunner、事件数据库与交互原型已经退役，不是当前依赖。

## 模块边界

- `task_progress.py`：公共事件 `TaskStep`、下载进度、取消异常，以及独立于 TUI 的任务状态模型。
- `plans.py`：固定任务计划、稳定任务标识、子任务事件合并；生成、组包与部署共享各自的计划构造器。
- `batch_workflow.py`：选择所需公共证书，按需申请，核对最终材料，再调用内存运行材料生成。
- `releases.py`：在内存准备运行材料、生成临时/离线包及读取旧批次；不申请证书、不进行 SSH 操作。
- `deployment.py`：探测版本、按需组包、先上传后部署，以及重试、跳过、停止处理。
- `public_tls.py`：单项签发及最多三个并发工作线程；并发调度只属于这项业务。
- `tui/task_progress.py`：显示事件、收集用户选择；不自行实现业务步骤。

## 计划与事件

执行开始时固定全部子任务和分组。内部标识如 `probe:<node_id>` 与显示名称分离。组合流程通过 `TaskPlan.map` 映射子流程事件，不使用手写索引偏移，也不依靠中文任务名称定位结果。

最多两级：多个大任务显示分组及子任务；仅一个大任务时隐藏重复的组标题。大任务串行，组内串行或并行由业务决定。事件顺序不能改变计划。

任务状态为 `pending`、`running`、`success`、`skipped`、`failed`、`stopped`。状态与结果文字分开，不能把“已保存”“安装成功”等文案当作协议。并发事件必须显式报告每项状态，不推断其他项目完成。串行生产者可通过切换活动项结束上一项。

总进度按已结束任务计数：多组时按大任务，单组时按子任务。失败有独立标识，不视为成功；未执行的任务不能因整体结束而自动成功。下载只在已知字节总量时显示百分比。

## 组合流程

- 部署当前设置：所需公共证书准备 → 内存生成配置与证书 → 节点部署。
- 导出 .run：使用同一准备流程，再准备完整二进制并组包导出，不 SSH。
- 存档与 JSON 导入导出：设置结构校验及原子持久化，不准备证书或运行材料。
- 没有公共 HTTPS 站点时省略公共证书组。

公共证书准备结束后重新检查配置和环境；不能用旧校验结果跨越网络任务继续生成。界面刷新内可以共享一份校验报告，但不能用界面缓存代替执行前检查。

## 停止与失败

使用协作式取消，不强行中断数据库提交。已成功签发的证书和完整缓存保留，不发布残缺文件。下载的共用实现检查取消、大小上限和已知 Content-Length。

探测失败可重试或停止；上传、部署失败可重试、跳过或停止。远端提交后连接中断，先查询完成状态，不盲目重复执行。任务结束后清理本地临时包，只有全部节点成功才尝试清理远端上传文件，不自动回滚。

所有流程共用进度弹窗；最终结果留在对应行，额外错误与清理警告单独显示。返回在执行期间禁用，停止需确认，结束后保留同一弹窗。
