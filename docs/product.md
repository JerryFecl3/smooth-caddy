# 产品与交互基线

本文件记录当前产品规则、模块边界及 TUI 交互基线。
当前实现支持配置维护、证书管理、配置批次生成、部署包导出与 SSH 部署。业务逻辑独立于 TUI，可通过 Python 接口调用。

## 定位与范围

面向个人和爱好者，在家庭／工作网络部署变化时维护一套多节点 Caddy 配置。
一个程序实例只管理一个网络；不提供多项目、多租户或多网络切换。
核心是区域、节点、站点三套配置编织成矩阵，加上配套证书管理。
所有节点自然承载所有站点，新增对象自动扩展矩阵；无逐站点节点绑定、无节点级站点规则覆盖。
不管理 DNS、iptables、nftables、NAT、端口映射、包升级清理或通用系统维护。
导出生成每节点离线 `.run` 部署包；可手动安装，也可由配套 SSH 流程上传并执行。SSH 与部署属于外围能力，复用相同发布物，不承担通用日常运维。

## 区域

全局区域名称唯一。默认提供内网、外网，可以增加 VPN 等区域。
每个区域提供默认 HTTP、HTTPS、中继 HTTPS 三个端口。
无区域继承、优先级或区域间自定义路由。
新增区域时：已有节点对应区域关闭，已有站点对应区域不提供服务。

## 节点

节点名称唯一，改名不改变身份和引用。
节点明确配置平台类型与 CPU 架构，供导出选择安装脚本、服务定义和官方二进制。首批目标为 Debian 13 与 OpenWrt 25.12；安装器不自动识别或改选平台。
每个区域仅有：启用状态、具体监听 IP、三个端口各自的可选覆盖值。
启用必须填写 IP；禁止 0.0.0.0、:: 等通配地址。未覆盖的端口实时跟随区域默认值；清除覆盖恢复跟随。
没有额外中继开关；区域启用后中继入口随之启用，关闭则一起关闭。
同一节点不得产生冲突的 IP + 端口用途。不同 IP 可以复用端口。

转发方式由上游节点决定：
- 直连源头：直接连接各 Site 的源头地址。
- 经上游转发：名称编辑框选择上游节点，中继上游选择该上游的区域，使用其具体 IP 与中继 HTTPS 端口。

一个节点全部站点、全部入口共用这套关系。禁止循环；引用对象必须存在且区域启用。
删除上游后保持“经上游转发”，不可自动退化为直连。
直连源头节点也可以接受其他节点的中继请求。
当前只支持单上游。

## 站点

站点名称唯一，域名另行全局唯一；一个站点只有一个域名，多个域名使用多条站点。
源头暂为不带路径、查询参数或片段的 http/https URL，可指定端口。
当前只支持单源头。
普通 HTTP/API/WebSocket 共用代理规则，不设 WS 开关。

每个区域选择一项：

| 原则 | HTTP 用户入口 | HTTPS 用户入口 |
| --- | --- | --- |
| 不提供服务 | 拒绝 | 拒绝 |
| HTTP | 提供服务 | 拒绝 |
| HTTPS | 跳转到本区域实际 HTTPS 端口 | 提供服务 |
| HTTPS + mTLS | 同上 | 验证用户证书后提供服务 |

无站点总开关；各区域关闭即可暂停用户服务。未知域名、未开放协议统一拒绝，无兜底站点。
中继不受中继所在区域的站点用户服务规则限制：区域不开放某站点，并不妨碍转发它。
用户入口验证用户，中继每一跳只验证双方节点，不再次验证用户身份。
所有中继使用 TLS + mTLS。

站点页底部提供“高级设置”，全局开关“校验 HTTPS 源头证书”默认开启；持久配置必须包含此字段。关闭时仅对直连 HTTPS 源头设置 `insecure_skip_verify`；HTTP 源头、用户入口及节点间 TLS/mTLS 和叶子绑定不受影响。变更后生成新配置批次并部署才生效，不增加逐站点选项。

## 证书体系

唯一私有根 CA，三个中间 CA：站点 TLS、用户 Client、中继。
所有新生成的私有 CA、Client、网站及中继证书保留现有 CN，并固定加入主体字段 `OU = Smooth Caddy`，用于标示生成程序，不参与授权、不提供编辑。已有证书不自动重签；公共 CA 签发的证书不修改。
站点用户入口可选择私有 CA 或公共 CA；用户 mTLS 与中继身份仍使用私有 CA。公共 CA 由独立 lego 模块管理，详见公共 TLS 章节。
私有证书与密钥的生成、签发、加密、改密和 PEM／P12 编解码通过 Python `cryptography` 库在进程内完成，不调用 `openssl`；公共 TLS 证书申请通过 lego 完成。
CA 初始化输入名称前缀（示例 Personal WEB），四个 CN 强制追加 Root CA、TLS CA、mTLS CA、Relay CA。名称保存与证书 CN 一致；既有证书保持原名，不自动重签。程序口令独立于 CA 初始化。
四个 CA、所有 Client、SSH 私钥统一使用程序口令加密保存。首次启动设置口令并立即生成 SSH 密钥，随后必须创建 CA 才能进入主界面；中途返回退出程序，下次启动继续补全。已有口令但缺失 SSH 身份或 CA 时，启动要求解锁后补全；初始化完整时首次受保护操作要求解锁，同一进程持续有效，退出清除会话。公共 TLS 的私钥、DNS 凭据及 ACME 私密状态使用相同口令保护。

| 材料 | 有效期 | 生命周期 |
| --- | --- | --- |
| 根 CA 与三个中间 CA | 固定到 2099-12-31 | 初始化生成，持续保留 |
| 私有网站 TLS 证书及私钥 | 签发日起 365 天 | 每次生成配置批次重新签发 |
| 中继服务端／客户端证书及私钥 | 签发日起 365 天 | 每次生成配置批次重新签发 |
| 用户 Client 证书及私钥 | 固定到 2099-12-31 | 手动签发，持久保存 |

私有 PKI 在数据库中保存四个 CA 与用户 Client 及其私钥；公共 TLS 模块独立保存申请所得的证书与私钥。自动签发的私有网站和中继叶子材料只保存到配置批次，不进入证书数据库。导出 package 或部署已有批次均不重新签发。

固定终止时间为 2099-12-31 23:59:59 UTC；子证书有效期不得超过签发者有效期。上述 365 天规则只适用于私有自动签发，公共证书有效期由 CA 决定。
网站、用户、节点身份不得因共用根 CA 而混用。
中继同一入口服务多个下级时复用服务端证书；每个下级持有自己的客户端身份。
上下游按明确关系绑定对方证书指纹；不能只凭同一中继 CA 签发就允许任意互通。
整套材料统一导出，换证衔接由配套部署工具负责，本项目不增加过渡信任流程。

Client：仅输入唯一签发名称，默认启用；可禁用、恢复、导出，不可单独删除，禁用名称仍占用。
所有用户 mTLS 入口固定为 CA 校验 + 启用 Client 的叶子白名单，无按站点授权，无认证模式开关。
空白名单拒绝全部 Client。签发、禁用、恢复要在节点更新后生效。
可单独导出 Client P12（证书、私钥、证书链），导出时输入密码。
“导出信任 CA”导出根 CA 的公开证书，默认文件名 `root-ca.cer`，DER 编码，不含私钥、不需要导出密码或解锁 CA。Windows 安装到受信任的根证书颁发机构；Android 安装为用户 CA，但应用是否信任用户 CA 由应用决定。信任范围包含共同根下符合用途的各条证书链。Caddy 继续提供网站证书与 TLS 中间链。

全局可修改程序口令：已解锁后只输入新口令及确认，不再验证旧口令。全部私钥与口令元数据在一个事务中重新加密，失败完整回滚；证书、密钥身份不变。
全局可重置四个 CA：单独确认危险操作，输入根 CA 名称，重新初始化并清除全部 Client。程序口令、SSH 密钥与配置不受影响。
区域、节点、站点、引用关系与服务规则不受重置影响。已导出文件及远端节点不会自动更新。
查看配置、证书、SSH 公钥及导出 CA 公开证书不要求解锁。所有配置修改、Client 启停、私钥使用、发布生成和删除、SSH 部署均要求程序解锁。配置本身仍以明文保存，修改权限由共享业务层检查；这不防止程序外直接修改数据库。
Client P12 导出先要求程序解锁，再单独输入一次明文导出口令。解锁、修改口令、P12 导出口令使用同一个可复用弹窗，支持原地错误提示，不提供“显示口令”开关：解锁时隐藏输入；P12 导出口令显示明文；首次设置及修改程序口令仍需两次明文输入；危险操作确认始终独立。

Client 的 P12 导出默认文件名为“证书名称.p12”；不适合作为文件名的字符替换为下划线，保留中文名称。P12 和信任 CA 导出路径固定在 `~/smooth-caddy-export/` 目录，弹窗只读展示绝对路径，不允许编辑；同名文件覆盖仍需确认。

危险操作确认后必须再次输入当前程序口令，验证通过才执行；已解锁状态不能跳过。此验证使用掩码输入，错误可重试，返回则不执行；不改变进程解锁状态，与 P12 导出口令独立。

危险操作仅限重置 SSH 私钥和重新初始化 CA 私钥。部署、删除配置批次或条目、覆盖导出文件、信任 SSH 主机及停止任务均采用普通确认（Ctrl+S／Enter），不增加额外口令验证。正常的首次解锁要求不变。

## 完整性检查

编辑允许暂时无效，除唯一性冲突以及新建名称未保存等情况外，不强制在弹窗中修完才保存。
格式、缺失、引用和监听冲突在相关单元格及导航标记，详情在编辑弹窗展示；这些配置错误阻止导出。SSH 地址错误只阻止 SSH 部署，不阻止离线生成。
无统一问题列表。删除区域／节点仅警告影响，不阻止；保留上游失效引用供修复。
删除区域移除所有节点和站点的相应区域配置，不留下站点悬空区域。
不调用 Caddy 做本地或远端配置预验证，不探测网络／站点实际可达性。

## 离线部署基线

### 配置批次、部署与 package

配置批次持久保存生成时的证书和各节点 Caddy 配置，不绑定 Caddy 版本、不保存 `.run`。metadata 包含 node、site、zone 的完整配置快照，以及文件路径、大小和 SHA-256；索引仅保存批次时间、三类对象名称摘要和 metadata 哈希。创建完成后才加入索引，不发布残缺批次。列表和生成结果均不展示目录，列表显示批次、节点数、站点数、区域数，详情提供名称摘要。

部署时选择 Caddy 版本，读取并验证所选批次材料，按批次保存的节点连接配置探测版本。匹配的节点仅携带配置，其余节点携带目标版本二进制；全程不要求选择包类型。二进制在本地全局缓存，按需下载及校验，不存数据库。每次部署都重新组装临时 `.run`，逐节点上传后逐节点部署。任务结束后清理本地临时包；全部成功后尝试移除节点上的上传包。清理失败明确提示，不把节点已成功部署误报为失败。

新增并部署先生成配置批次，再执行上述流程。部署及导出始终使用该批次固化的材料，不读取当前编辑配置重新生成材料，也不重新签发证书；原证书有效期继续适用。

导出 package 选择配置批次和目标版本，始终包含各节点所需的官方标准版二进制，支持目标机离线部署。固定输出至 `~/smooth-caddy-export/packages/<导出时间及唯一后缀>/`，每个节点一个 `.run`。不建立导出索引、数据库记录或管理列表；仅导出成功后展示路径，文件由用户管理。

### 发布命名与保留

配置批次名为生成时间，精确到秒。同秒创建等待下一秒，避免重名。批次保存在 数据目录内的 `releases/`，仅接受索引格式 3，不兼容旧安装包索引。后续格式升级按正式发布兼容基线实施版本迁移。

数据目录内的 `.tmp/tasks/` 是临时部署包目录；临时任务及 package 导出目录使用时间与随机后缀避免冲突。所有持久路径均为相对于数据目录的路径。元数据及材料不含本地主机绝对路径，整体复制后可继续使用。

节点侧仍保留最近 5 份成功配置，使用配置批次标识作为逻辑版本；相同批次重新部署复用该逻辑版本，不重复签发。失败不自动回滚，旧版本可手动恢复；二进制独立复用，不自动清理。跨批次中继身份不保证互通。

### 权限与检查

安装器预设调用者已具备系统级安装权限，不提供用户级安装模式、不自动 sudo，也不单凭 UID 判断；检查实际可写性和服务管理能力。
Caddy 暂以 root 运行，Debian 使用系统级 systemd，OpenWrt 使用 procd。
前置检查仅涉及 CPU 架构、预选服务管理器、目标路径权限和基础工具，不检查 IP 是否已配置、端口是否占用或网络可达性，不自动安装依赖。

### 固定文件布局

| 用途 | Debian | OpenWrt |
| --- | --- | --- |
| 辅助脚本与启动入口 | `/usr/local/lib/smooth-caddy/` | `/usr/lib/smooth-caddy/` |
| 二进制 | 上述目录的 `binaries/<版本>/<架构>/caddy` | 同左 |
| 各批发布配置、证书和清单 | `/etc/smooth-caddy/releases/<发布时间>/` | 同左 |
| 当前选用发布 | `/etc/smooth-caddy/current` | 同左 |
| 持久运行数据与部署状态 | `/var/lib/smooth-caddy/` | `/etc/smooth-caddy/state/` |
| 安装锁等临时状态 | `/run/smooth-caddy/` | `/tmp/smooth-caddy/` |
| 系统服务定义 | `/etc/systemd/system/smooth-caddy.service` | `/etc/init.d/smooth-caddy` |
| 默认日志接收方 | journald | logd |

OpenWrt `/var` 通常指向临时目录，因此不用于保存这些持久材料。固件升级后的安装保留不纳入当前范围。

### 部署、重试与恢复

包内清单记录节点身份、包格式、平台、架构、确切 Caddy 版本、发布版本及文件校验值；不能依靠文件名判断。
先解包、检查完整性并准备完整新材料，再切换发布，避免在正在使用的目录中逐个覆盖文件。
配置与证书整体切换，服务使用该发布绑定的二进制。启动／重新加载后观察进程持续运行，不运行 Caddy 配置预验证或实际站点访问测试。
失败保留当前选用发布与故障信息，不更新“最近成功发布”、不清理旧发布、不自动恢复；两种状态必须分开记录。
固定辅助入口分别提供“列出本地发布”与“切换指定发布”命令，不要求用户手工编辑符号链接。命令为 `manage list` 和 `manage switch <批次标识>`。

## SSH 部署边界

每个节点仅配置一个 SSH IP，使用 root、端口 22，不增加用户名和端口选项。SSH 路径沿节点的 Caddy 上游关系逐级跳转；区域选择用于 Caddy 中继入口，SSH 使用对应节点自己的 SSH 地址。默认节点允许跳板转发，不再引入独立 SSH 拓扑。

首次启动设置程序口令时生成并加密保存一套共用 SSH 私钥，可明确确认后重置。节点信任公钥由使用者按引导手动配置，程序不承担首次密码登录或自动安装公钥。持久记录程序私钥与连接过的节点主机指纹，不保存登录密码；重置程序私钥不清除主机指纹。
每一跳首次连接须确认主机身份；指纹变化时停止并明确重新确认，不能静默接受。程序私钥不复制到节点。

部署已有配置批次使用该批次固定的配置、证书材料及 SSH 地址与路径。当前配置编辑或 CA 重置不改变已有批次；所选批次的文件完整性及目标连接关系仍须有效。
全部节点统一确认，暂逐个执行：先依次上传全部安装包，再依次安装并检查服务持续运行。失败暂停，提供重试、跳过、停止；上传跳过的节点不进入安装。停止保留已完成操作，无自动回滚。安装时连接中断不能直接判断失败，应先重连查询结果。

## 实现边界与模块化

当前工程以本文件为产品基线。旧实现和原型已退役，不随程序分发；首次公开发布以前的开发历史仅在本地归档，公开仓库从审核后的干净提交开始。

正式实现是一个 Python 程序，不引入多服务或插件系统。TUI 和未来 CLI 是并列入口，共用独立应用接口层；TUI 不通过执行自身 CLI 子进程实现业务。

应用接口层承接完整业务操作、参数校验、执行流程、结构化结果、进度和需要用户决策的状态，不依赖 Textual，不读取键盘或输出界面。TUI 负责输入、展示和提交用户决策，不直接操作数据库或实现签发、配置生成、打包、部署逻辑。
配置管理、证书管理、Caddy 配置生成、二进制缓存、部署包 管理、SSH 连接及部署执行保持明确职责；跨模块流程由应用层组织，不互相读取内部状态。

CLI 指 Linux shell 中独立执行、完成后退出的命令。可在 TUI 定型后实现；命令格式、参数和 help 由实现阶段确定，每项业务能力最终都须可从 CLI 调用，与 TUI 共用默认值、校验及执行逻辑。验收标准是去掉 TUI 后，业务仍可通过 Python 接口独立调用和测试。

## 交互基线

当前 TUI 作为正式实现的交互基线，后续在使用中微调。键盘可完成全部操作，支持鼠标；普通桌面终端优先，不过度适配小屏；矩阵允许横向滚动，保持名称列和表头，选中项随滚动可见。

### 页面与内容

首屏为部署页。主界面仅有软件标题及三个操作区域：左侧导航、右侧上部内容、右侧底部操作。主界面不展示解释性文案、重复页面标题、状态摘要、选中项说明或消息条；必要解释、错误详情和危险操作影响放入编辑／确认弹窗。

| 导航 | 内容与选择方式 | 条目默认操作 | 其他操作 |
| --- | --- | --- | --- |
| 部署 | 配置批次列表，整行选择 | 详情 | 新增、删除、新增并部署、SSH 公钥、重置 SSH 密钥；详情中部署、导出 package |
| 站点 | 站点 × 区域矩阵，单元格选择 | 编辑 | 新增、删除 |
| 节点 | 节点 × 区域矩阵，单元格选择 | 编辑 | 新增、删除 |
| 区域 | 区域与默认端口列表，单元格选择 | 编辑 | 新增、删除 |
| mTLS证书 | Client 列表，整行选择 | 无；Enter 不执行动作 | 启用／禁用、签发新增、导出 P12、进入 CA 管理 |

CA 管理是 mTLS证书页的二级页面。未初始化时提供“初始化 CA”，已有 CA 时同一入口显示“重新初始化 CA”；后者先确认清除全部证书及 Client，再进入初始化。另提供导出信任 CA 和返回证书。修改程序口令位于全局导航；受保护操作自动调用统一解锁弹窗。SSH 功能位于部署页，不放在 CA 页。

节点列顺序为：**名称、平台／架构、SSH 地址、WEB服务地址(区域名)、中继上游IP**。

- 平台与架构合并展示，编辑框仍是两个独立选择项；任一项错误均标记在合并列。
- 新增／编辑名称时可选上游节点；保存前检查完整上游链，自引用或间接成环拒绝保存。上游同时决定 SSH 跳板与 Caddy 转发关系。名称列按稳定树形先序排列，使用树状符号表达上下游；同级保持原顺序。
- 中继上游为最后一列，只选择上游节点的区域；无上游时单元格留空且不可编辑；选项显示“节点名-区域-IP”，保存后单元格仅显示 IP。更换上游清空原区域，取消上游恢复直连。未选择区域允许保存但阻止生成批次，不影响 SSH 路径。删除上游保留失效引用，不能自动变成直连。
- 区域单元格集中编辑启用、监听 IP 和各端口覆盖；未覆盖端口跟随全局默认值。
- 站点按名称、域名、源头地址、TLS 来源、各区域排列，区域服务规则在区域单元格中编辑。

新增先输入唯一名称；保存名称后保留新行，继续复用已有条目的编辑行为。未保存名称时取消，不产生条目。删除节点／区域的确认框说明受影响引用；允许删除后保留错误，待用户修复。
Client 名称固定，不能改名或单独删除。选中行后，底部普通按钮随状态显示“启用”或“禁用”，不使用默认重点色或 Enter 提示；按钮、Ctrl+T 调用同一切换操作。

站点页面每次进入时重新加载并按名称排序（忽略大小写）；停留页面期间保持行顺序，新建条目追加到末尾，编辑名称不立即重排。

### 导航与焦点

主界面 Tab／Shift+Tab 在导航、内容、底部操作三者之间循环；方向键只在当前区域内移动。

- 导航主模块随方向键高亮即时替换右侧内容，焦点仍留在导航。Enter／空格选定页面并进入内容区。
- 帮助、退出位于侧栏，移入焦点不切换页面、不执行动作，确认后才执行。
- 内容区方向键移动单元格或行；底部操作栏方向键在可用按钮间循环。
- 弹窗使用独立焦点范围，Tab／Shift+Tab 在弹窗控件间移动；不响应主页面导航快捷键。
- Esc 依次退出展开控件、弹窗、二级页面；主页面无可退出层级时返回导航。已在导航时再次 Esc 不退出程序。进行中的任务先确认停止。

Enter 执行当前焦点控件的默认操作，不由全局 Enter 抢占。配置单元格打开编辑，配置批次行打开详情；证书行无默认操作；按钮焦点下 Enter 点击该按钮。危险确认框例外：Enter 和 Ctrl+S 均不执行确认，使用 Ctrl+Y 或鼠标点击确认按钮。危险确认按钮统一使用红色，焦点仍遵循全局蓝色；返回按钮在显示快捷键时标注 Esc。

### 弹窗控件与按钮

| 控件 | 方向键 | Enter／其他操作 |
| --- | --- | --- |
| 文本输入框 | 上／下切换控件；左／右移动文字光标 | Enter 与 Ctrl+S 使用同一表单保存逻辑 |
| 收起的下拉框 | 方向键切换控件，不展开选项 | Enter 展开，鼠标点击也可展开 |
| 展开的下拉框 | 上／下选择选项 | Enter 确认选项，Esc 只收起下拉框 |
| 勾选框 | 方向键切换控件 | Enter／空格切换；明确显示 `[x]`／`[ ]` |
| 按钮 | 上／下移动控件焦点；左／右在按钮间移动 | Enter 点击当前按钮 |

焦点移动跳过隐藏、禁用控件和滚动容器。取消不修改原值；错误允许暂存的边界按完整性检查规则执行。
所有业务操作提供按钮，表格默认操作也有同名按钮。弹窗统一提供返回按钮，纯信息弹窗仅提供返回按钮；展示快捷键时返回标记为 Esc。

主页面底部操作栏：默认操作最左，常用操作随后；全局、低频操作靠右，最高危操作最右，中间以弹性空白分隔。证书列表无默认操作。CA 管理没有条目列表，其页面级操作统一放右。
**所有弹窗按钮组统一靠右**，不使用左右分组空白。

所有弹窗均提供右对齐的“返回”按钮，返回不保存当前编辑，Esc 继续保留返回行为。帮助和 SSH 公钥展示弹窗仅提供“返回”，不提供保存或确定。生成过程中返回按钮暂不可用；部署执行时返回按钮禁用，使用停止结束后续工作，执行结束后启用返回。

底部按钮按操作范围分组：条目操作位于左侧，当前默认操作最左，新增等操作随后，删除位于该组末尾，导出 P12 若存在则排在删除之后；页面及全局操作位于右侧。SSH 公钥弹窗将密钥类型和公钥保持在同一行，窄窗口可横向滚动；Debian 使用 OpenSSH 的 `~/.ssh/authorized_keys`，OpenWrt 使用 Dropbear 的 `/etc/dropbear/authorized_keys`。说明要求授权登录用户具备所需权限，SSHD 允许跳板转发。

### 视觉与错误提示

软件标题、激活导航、未聚焦的默认操作共用墨绿色重点色；标题使用终端原生字号、加粗和上下留白，不单独改变字号。
光标统一为蓝色：导航焦点背景覆盖激活背景，内容区单元格／行使用蓝色，所有区域的按钮聚焦时整块变蓝，包括上下边缘。危险按钮未聚焦时保留警示色；首列不使用特殊底色。

按钮最小宽度为 16 个终端字符格，按实际可见文案计算；隐藏快捷键时短按钮基本同宽，显示快捷键或文案较长时扩展。文字水平、垂直居中；必要时增加一格，使中英文混排的左右空白对称。

配置错误是主界面精简文案规则的例外：相关导航显示单个 `!`，标签为红字，不显示错误计数；激活或聚焦时仍保留红字，修复后恢复。相关表格单元格保留错误标记，详细原因在编辑弹窗显示；无全局问题列表。

表格采用两级选中提示：单元格模式下，当前整行使用浅蓝色背景，选中单元格使用统一光标蓝色。整行选择模式下，全部单元格（含固定首列）使用相同蓝色；焦点移到导航或底部操作按钮后，选定行保持原色，不套用不同的失焦颜色。

导航顺序为部署、站点、节点、区域、mTLS证书、TLS证书，对应 F1～F6。滚动条统一为中性灰色。节点、站点、区域名称列宽为 11，mTLS 证书名称列保持 18，TLS 域名列固定为 32，不随窗口拉伸；平台架构列宽 20，SSH 地址按实际地址长度在 15～39 内调整，端口列按标题宽度紧凑排列。

### 部署页面流程

列表读取配置批次索引，展示批次、节点数、站点数、区域数，不展示目录、Caddy 版本或类型。

- 新增：确认后保存配置批次，不联网查询版本。
- 详情／行 Enter：默认操作，展示节点、站点、区域名称摘要，不展示路径。部署和导出按钮仅位于详情弹窗中。
- 新增并部署：选择版本，一次确认后新增配置批次并部署。
- 详情中的部署：选择目标 Caddy 版本，确认后逐节点探测、按需组装临时包并部署。
- 导出 package／Ctrl+E：选择版本，生成完整离线安装包，仅成功后显示路径。
- 删除：删除配置批次及索引，不影响节点已部署配置和已导出的 package。
- SSH 公钥和重置密钥：沿用独立身份管理流程。


## 当前实现与数据约定

默认入口为 `smooth_caddy.py → app.entry → app.tui`。旧实现与内存原型已归档，不随程序分发。

业务层位于 `app/network/`：`models` 定义配置与校验，`storage` 管理 SQLite 与配置修订，`application` 提供编辑命令，`certificates` 管理 Python PKI，`generator` 生成节点材料，`releases` 管理二进制缓存、配置批次及临时打包，`deployment` 管理 SSH 信任及分阶段部署。所有业务模块不导入 Textual；当前先交付 TUI，完整 shell 命令面后续接入相同接口。

运行数据写入 数据目录内的 `smooth-caddy.db`，不会就地转换旧库。数据库有独立所有权标记与版本检查；配置保存使用修订号避免覆盖并行修改。`security` 负责共享口令会话及私钥加密；Scrypt 从口令和随机盐派生密钥，Fernet 提供认证加密。全部持久私钥均在数据库内加密，无独立解密文件。口令和解锁材料只保留在进程内，不写日志或配置；退出释放引用，不承诺 Python 内存物理清零。已生成安装包中的运行私钥保持可由目标机直接使用，P12 使用独立口令。

正式安装模板位于 `app/network/templates/`。配置批次保存自动签发的叶子证书，私有证书数据库保留 CA 与用户 Client，公共模块另行持久保存公共材料。打包时读取固化材料，内部安装清单仍记录节点、架构、目标 Caddy 版本和校验值；导出的 package 没有额外持久记录。

官方版本列表查询失败时，弹窗显示具体失败原因，保留本地版本供选择。GitHub 返回包含资产与说明的完整发行元数据，版本列表请求允许最多 16 MiB，避免将正常响应误判为超限。

部署与导出 package 的版本选择以版本矩阵当前行为准，不允许手动指定版本。联网刷新保留选择，无候选版本时禁用操作。创建配置批次无需版本选择。

SSH 部署返回非零时，失败弹窗同时保留退出码、标准输出和标准错误，并尝试限时读取最近的服务日志；不因诊断停止其他服务或自动修改监听端口。

正式安装器在重启前记录旧 PID；重启后最多观察 30 秒，忽略旧 PID 和进程交替的空档，仅在新 PID 连续存活 3 秒后确认成功。未达到条件仍失败并保留现场，不自动回滚。此检查不验证站点可达性。

配置批次、临时包及 package 使用固定内部目录，不提供目录编辑。版本列表先展示缓存，后台联网刷新；不可选的刷新提示完成或失败后移除。

版本列表缓存同时保存 HTTP ETag／Last-Modified；后续使用条件请求，304 时直接复用本地 JSON，不下载完整响应。校验元数据与缓存内容对应，避免损坏或旧缓存误用。版本查询网络等待为 10 秒，界面刷新总等待上限 20 秒；超时结束刷新提示并保留已有列表。

配置批次索引格式 3；`metadata.json` 格式 1，保存配置快照和各节点材料清单。索引中的目录及材料路径相对当前数据目录，不自动迁移旧路径。

取消禁止兼容层的限制。以首次正式发布格式为兼容基线，不追溯支持所有开发期格式。后续持久数据升级使用显式版本迁移，迁移前备份，遇到更新格式拒绝写入。程序版本与数据库、批次、部署包格式版本分别管理。当前实现仍只接受数据库版本 2、配置批次索引格式 3，尚无自动迁移实现。

Caddy 二进制下载以分块进度展示版本、架构、进度条、已下载／总大小及平均速度，并明确区分校验清单、连接服务器、下载、校验解压和使用本地缓存。服务器未提供总大小时使用不定进度，保留已下载大小和速度，不推测百分比。下载完成后继续显示证书生成及节点打包阶段。

### 统一任务进度

确认后总步骤一次固定。创建批次包括证书配置生成、各节点保存及 metadata；部署包括探测、准备 Caddy、各节点打包、上传及部署；涉及公共 TLS 时，新增批次先执行“申请公共TLS证书”；新增并部署再串行执行“生成配置批次”和“部署到节点”，展开生成批次的实际子任务。架构下载数量不改变总步数，单个下载使用当前步骤进度条。无需下载时明确显示，不能计量的步骤仅显示状态，不推测百分比。

统一展示最多两级任务。只有一个大任务时只展示子任务；多个大任务时展示大任务及其子任务。大任务串行，子任务由业务决定串行或并行，固定顺序展示、独立记录状态，乱序完成不能推断其它任务完成。大任务显示已结束子任务数，失败单独标识；总体进度以大任务数（单组时以子任务数）计数。总体进度和耗时位于同一行。返回在执行期间禁用，Esc 不关闭正在运行的任务。停止需要独立确认并等待安全检查点；生成批次不发布残缺数据，临时打包的失败产物清理，缓存始终复用。失败可重试，不自动回滚或恢复；探测只允许重试、停止，部署支持重试、跳过、停止，远端结果未知时先查询。

完成或失败保留同一弹窗，不叠加成功提示。配置批次标识及各节点结果融入对应子任务行，不另行重复汇总、不显示配置批次路径；仅 package 导出成功显示输出路径。主机指纹确认独立于任务确认。

进度列表每一步均显示状态或结果：探测仅显示实际版本（无版本时显示未部署），打包仅显示已打包，上传及部署显示实际结果；尚未执行的步骤显示等待中或未执行，失败及跳过不标记为成功。

## 独立公共 TLS 模块

主导航提供“TLS证书”独立页面。模块独立负责配置、申请、数据库存储及 lego 管理；站点通过 TLS 来源选择使用已有公共材料，组合流程负责按需申请及批次生成。私有 CA 重置不清除公共 TLS 记录。

- 仅使用 Let’s Encrypt，模块级测试模式默认开启；测试与正式环境共享配置条目和 DNS 凭据，证书、私钥、有效期、错误及 ACME 状态分别保存。切换环境仅切换申请结果，不跨环境使用证书；已启动的申请固定使用启动时的环境。
- 每条记录独立填写域名、通配选项、DNS 服务商及凭据。支持阿里云和 DNSPod（lego 的 tencentcloud），不聚合、不共享、不继承凭据。
- 通配申请同时包含基础域名及其一级通配域名。域名范围保存后固定；改变范围需新增记录。编辑凭据时留空保留，更换服务商必须重新填写。
- 新增只保存配置；详情提供申请、强制申请和编辑。申请成功后校验域名、有效期、证书与私钥匹配及提供的证书链签名，再原子替换材料；失败保留旧材料。尚未签发的记录可保存。
- 普通申请复用剩余有效期超过 13 天的材料；其他情况交给 lego 执行。强制申请重新请求材料。使用统一任务进度框，无后台定时续期。生成新批次时按需申请或续签。域名全局唯一，通配与否不影响唯一性。全部申请对当前环境的记录最多并发 3 条，复用无需更新的证书；失败不影响其余记录，停止取消在途任务并不再启动等待记录，保留已完成结果。
- 现有数据库的键值表以 public-tls/ 保存公开元数据，以 public-tls-secret/ 加密保存每条记录的 DNS 凭据、私钥和 lego 工作状态。纳入统一口令修改事务，后续结构升级纳入统一版本迁移。
- 执行时恢复至权限受限的临时工作目录，结束后删除。ACME 账户失效时重建该记录的账户并重试一次。中断、网络错误可能留下 DNS 验证记录，不把本地停止视为云端撤销。
- lego 管理显示本地版本，手动检查官方最新兼容 v5 版本，按运行主机平台和架构下载；核对官方 SHA256 清单、执行版本检查后原子替换，失败保留旧工具。工具文件位于 数据目录内的 `tool_lego/lego`，不入数据库、不下发节点；签发不自动下载更新。
- 首版自动化测试使用 ACME 与 DNS 替身，不表示真实 DNS 服务商申请已验收。

### 站点公共 TLS 与批次生成

- 每个站点的 TLS 来源为“私有 CA”或“公共 CA”，默认私有 CA，所有区域共用。HTTP 和中继证书不受影响。
- 当前公共 TLS 环境内按精确域名优先、一级通配其次匹配，不手工绑定条目。生成时验证实际证书覆盖范围及私钥，不回退到私有 CA。
- 统一本地检查区分阻断错误（无匹配配置、损坏材料、解锁后发现 DNS 凭据缺失或密钥不匹配）和待处理状态（待申请、待续签）。后者展示在站点 TLS 来源列，不阻止进入流程。锁定时不解密材料；解锁执行前重新校验。
- `app/network/batch_workflow.py` 编排公共证书准备与批次生成，TUI 不实现业务编排。只对需要 HTTPS 的站点匹配记录，去重后最多并发 3 条；不申请无关记录。任一申请失败则停止生成，保留已经成功签发的材料。
- 首先固定全部任务及分组，再开始执行；申请结束重新核对配置、环境和材料。证书与私钥通过明确参数传入底层生成器，生成器不查询公共证书库、不访问 ACME。
- 批次保存公共完整链和私钥快照，不追加私有 CA 链；私有站点证书及中继身份仍按原流程生成。已有批次的部署和导出不触发签发，也不依赖当前公共 TLS 记录是否存在。
- 测试环境生成确认提示“包含公共 CA 测试证书”。没有公共 HTTPS 站点时省略公共证书阶段。

## 当前实现结构

生产入口只使用 `app/network` 和 `app/tui`，旧实现、原型和独立实验脚本已归档退役。当前测试只覆盖受支持的入口和产品功能。

TUI 通用弹窗在 `dialogs.py`，区域／节点／站点编辑在 `configuration.py`，使用说明在 `guide.py`，公共 TLS 和部署页面分别在各自控制器中。页面刷新共享一份 `ValidationReport`，不逐单元格全量校验；执行任务前和证书申请后重新检查。

域名唯一性共享规范化规则。公共证书预检查与续签使用 `certificate_policy.py`；底层 HTTP 下载使用 `downloads.py`，原子写入使用 `files.py`。任务计划及状态约束见 [任务系统](supertaskrunner.md)，证书接口见 [证书模块](ca-lite-interface.md)。

自动测试使用临时数据库、网络与 SSH 替身，不等同于真实 DNS 签发、Debian/OpenWrt 实机、自启动、恢复和跨架构验收。

## 程序发布计划

版本与标签规则以 [README 的版本与发布约定](../README.md#版本与发布约定) 为准：首次标签 v0.1.0，发布物版本 X.Y.Z.commit；每次提交原则上增加 Z，数据结构变化增加 Y 并将 Z 归零。推送版本标签触发 GitHub 构建，本阶段仅 Linux x64、Windows x64。仓库公开，项目采用 MIT；工作流位于 .github/workflows/release.yml，项目许可文本位于 LICENSE。

开发保留模块化工程目录。GitHub Releases 计划提供独立可执行文件，优先采用 PyInstaller，按运行主机的操作系统与 CPU 架构构建；目标机器无需自行安装 Python。Linux 和 Windows 的运行数据默认保存在当前用户主目录下的 `~/.smooth-caddy/`，不再嵌套 `data/`，发布物不包含用户数据库、私钥、证书或下载缓存。

构建入口为 `tools/build_release.py`，构建依赖位于 `requirements-build.txt`。构建采用精确 Git 标签与提交哈希定版，Linux x64、Windows x64 分别在 GitHub Actions 测试构建，ARM 发布暂缓。发布前须验证资源定位、独立环境启动、数据搬迁和核心操作，确定平台兼容范围、数据升级策略及许可证。程序发布物不同于部署到 Caddy 节点的 `.run` 包。

第三方声明按实际分发物整理：独立程序覆盖内置 Python 与全部随附依赖，含二进制的节点包覆盖 Caddy 及其依赖。发布时随附对应版本要求的许可证、版权及 NOTICE（如有），网页入口仅用于阅读说明。独立程序构建收集并随包携带 Python 依赖许可，build-info.json 记录清单与未识别的系统库。

项目名称为 Smooth Caddy，命令与服务名为 `smooth-caddy`，源码入口为 `smooth_caddy.py`。数据库文件继续使用 `smooth-caddy.db`；数据库所有权与加密校验常量属于存储格式，不随品牌名改变。旧配置批次固化了旧部署路径，改名后应重新生成批次；目标机旧服务须由用户停用，新服务不自动接管旧目录。

独立程序和源码运行均通过 `Path.home()` 确定用户主目录，默认数据目录为 `~/.smooth-caddy/`，支持 `--data-dir` 覆盖；内置样式和部署模板继续从资源目录读取。构建输出包括单文件程序、说明、许可证目录、构建环境记录与压缩包 SHA-256。当前许可证收集仅作为审核材料，不声明已完成公开分发审核。

CA 管理无需解锁即可查看公开证书树：根节点展示实际根证书 CN，下一层依次为 Relay CA、TLS CA、mTLS CA；Relay、TLS 下显示省略号，mTLS 下展示已签发 Client，禁用者标记 `[disabled]`，无 Client 时显示“暂无证书”。各实际证书的到期日期独立右对齐，读取证书内容；不显示解锁状态。新建 CA 前缀及 Client 名称只允许 ASCII 字母、数字、空格、连字符、下划线、句点，保存时去除首尾空格；已有名称保持原样。

首次启动以一个“初始化”弹窗收集初始化口令、确认口令与初始化根CA名称。按钮为“退出”和“保存”；保存后生成受统一口令保护的 SSH 密钥及四个 CA，不再分两次填写。提示文案为：“使用本软件前，必须设置一个口令。本程序将生成SSH密钥及根CA私钥，私钥均将受到以上口令保护。请妥善保管本程序的口令及数据目录。”新口令两次输入保持明文展示；校验失败留在原弹窗，退出不创建材料。

界面文案使用名称、用途及实际状态，不将内部操作流程写成提示。字段使用“名称”等简短标签；输入限制、错误原因、凭据保留规则、服务条款及删除／重置风险保留必要说明，操作引导集中在使用说明中。

同一数据目录只允许一个运行实例。启动持有单实例锁，在后台线程清空数据目录内的 `.tmp/`，清理完成前不启动业务任务；退出等待任务结束后在后台线程清理，再释放锁。下载、解压、ACME 工作文件与导出中间材料都使用数据目录内的 `.tmp/`。证书导出到 `~/smooth-caddy-export/`，部署包导出到 `~/smooth-caddy-export/packages/`，完整生成后发布，失败不覆盖已存在的导出文件。导出目录通过 `Path.home()` 定位，在导出时创建，不随 `--data-dir` 改变；内部记录相对路径，界面展示绝对路径。
部署导航始终可用，默认进入部署页面；配置缺失或错误沿用校验提示。首次初始化在未编辑过的空配置中加入 Private、Public 两个区域，HomeRouter、CloudServer1、CloudServer2 三个节点，以及 Blog、Dashboard 两个站点。节点平台、地址、上下游及站点域名、源头、服务方式采用初始化示例；不自动创建公共 TLS 申请配置、不申请证书或部署。后续启动及 CA 重置不重复添加、不覆盖已有配置。

节点的 WEB服务地址(区域名) 列显示 `IP : HTTP端口/HTTPS端口`，端口取节点覆盖值或区域默认值；关闭区域仍显示“关闭”。中继上游IP 列仅显示已选上游区域的 IP。

配置批次材料使用独立随机 Fernet 密钥进行认证加密，批次元数据及列表摘要保持明文。密钥初始化时生成，经程序口令加密保存在数据库，不提供修改入口；修改程序口令仅重新加密此密钥，CA/SSH 重置不影响它。读取批次材料须解锁。
手动导出的部署包使用独立口令加密载荷（AES-256-CBC、PBKDF2-HMAC-SHA256、100000 次迭代、随机 8 字节盐，派生密钥及 IV），不增加身份认证或防篡改机制。导出口令明文输入一次，同次导出的各节点共用口令但各自随机盐。目标机需要 openssl 命令，交互输入口令后解密部署；口令不进入包内或命令行参数。SSH 部署仍生成临时明文包，经 SSH 传输，结束后清理。
